# ТЗ: Паола Lite — версия для кнопочного телефона (Sharp 501SH)

Статус: черновик на согласование с Юлией. Исполнитель — сессия Claude Code.
Перед началом прочитать `CLAUDE.md` (корень репозитория) и `paola-app/README.md`:
правила проекта действуют полностью (работаем только в `paola-app/`,
подтверждение перед пушем, мерж в `master`, финальный чеклист в Notion).

## 1. Зачем

Юлия переходит на раскладушку Sharp AQUOS Keitai 501SH. На ней не работают
приложения Google Calendar и Notion, поэтому календарь и задачи должны
открываться в браузере телефона через Паола App. Текущий интерфейс (`/`,
`static/app.js`, ~900 строк современного JS) на этом устройстве не заработает.

Нужен второй, параллельный интерфейс — **Lite** — на тех же данных и том же
бэкенде. Основной интерфейс (`/` и `/api/*`) не меняется.

## 2. Ограничения устройства (определяют все решения)

| Ограничение | Следствие для реализации |
|---|---|
| Android 5.1.1, системный WebView/браузер ~2015 года, не обновляется | Страницы рендерятся на сервере. **JavaScript не используется вообще.** Только HTML + минимальный CSS 2.1 |
| Нет тачскрина: D-pad (фокус по ссылкам и полям) + курсор-тачпад | Каждое действие — ссылка или кнопка формы. Контрастная рамка фокуса. Одна колонка, никаких hover-меню, свайпов, модалок |
| Мобильный интернет — 2G/EDGE (десятки кбит/с), иначе Wi-Fi | Бюджет страницы: HTML ≤ 15 КБ до сжатия, CSS встроен в страницу (≤ 3 КБ), ноль картинок, шрифтов и внешних ресурсов. Один запрос = одна страница. Включить gzip |
| Экран 3,4", 540×960 | Крупный шрифт (не меньше 18px), длинные названия переносятся, а не обрезаются |
| Старый набор эмодзи | Новые эмодзи (например 🪞 в зоне Personal) покажутся квадратами. В Lite эмодзи из зон, приоритетов и календарей не выводить — см. п. 5.6 |
| Клавиатура: цифры и латиница; кириллицы в прошивке, скорее всего, нет | Ввод текста сведён к минимуму. Числа вводятся через `type="number"`. Создание задачи — необязательный экран с коротким латинским текстом |
| Старое хранилище корневых сертификатов | Риск: сертификат домена Railway может не приниматься браузером. См. п. 3 — это проверяется до начала разработки |

## 3. Шаг 0 — проверка на устройстве (до написания кода)

Делает Юлия, результат сообщает исполнителю.

1. Открыть в браузере телефона `https://<домен Паола App>/healthz`.
2. Если видно `{"ok":true,...}` — всё в порядке, идём дальше.
3. Если ошибка сертификата — разработку не начинать, выбрать обход:
   - **A (предпочтительно):** свой домен через Cloudflare-прокси перед Railway
     (у Cloudflare цепочка сертификатов, которую знают старые Android).
     Ручной шаг в Railway/Cloudflare, кода не требует.
   - **B:** установить на телефон через ADB браузер со своим хранилищем
     сертификатов (старая версия Firefox для Android 5).
   - **C:** установить корневой сертификат ISRG Root X1 в настройках телефона
     (если меню безопасности доступно в прошивке).

   HTTP без шифрования как обход **не рассматривать**.

## 4. Архитектура

- Новый модуль `paola-app/lite.py` с `APIRouter(prefix="/lite")`,
  подключается в `main.py` одной строкой `app.include_router(...)`.
- Шаблоны — Jinja2 с включённым autoescape (названия задач и событий приходят
  из Notion/Google и должны экранироваться). Папка `paola-app/templates/lite/`.
  Добавить `jinja2` в `paola-app/requirements.txt`.
- Данные — только через существующие функции `services/notion.py`,
  `services/gcal.py` и хелперы `main.py`. Новых запросов к Notion/Google не
  писать, если существующая функция даёт нужное. Логику группировки задач
  («просрочено / сегодня / остальные») не дублировать: вынести из
  `get_tasks()` в `main.py` в общую функцию и использовать её из обоих мест.
  Поведение `/api/tasks` при этом не должно измениться.
- Все изменяющие действия — HTML-формы `method="post"`, ответ — `303 See Other`
  на страницу, с которой пришли (паттерн Post/Redirect/Get, чтобы «Назад» и
  обновление страницы не повторяли действие).
- `GZipMiddleware` (FastAPI) для ответов `/lite/*`. Убедиться, что на
  существующие `/api/*` и `/static/*` это не влияет негативно.
- Заголовок `Cache-Control: no-store` на всех страницах Lite.
- Anthropic API не используется (как и во всём приложении).

## 5. Экраны

Общее для всех страниц: шапка с названием экрана и датой, внизу — нумерованное
меню разделов. Текст интерфейса на русском (отображение кириллицы работает).

### 5.1 `/lite/login`
Форма с одним полем и кнопкой. Поле `type="password"` с `inputmode="numeric"`.
См. п. 6.

### 5.2 `/lite` — Сегодня (стартовый экран)
1. Дата и день недели.
2. **Встречи сегодня**: время — название. Источник: `gcal.get_events_full(days=0,
   from_now=True)`, как в `/api/calendar`. Если прошедшие скрыты — строка
   «прошло: N». Долгие события (`long`) — отдельной строкой через
   `gcal.format_long`. Если `GOOGLE_TOKEN_JSON` не задан — строка «календарь не
   подключён», страница не падает.
3. **Просрочено** (N) и **Сегодня** (N): списки задач; каждая задача — ссылка
   на `/lite/task/{id}`. Приоритет показывается оформлением карточки (п. 7).
4. Меню: `1 Завтра · 2 Неделя · 3 Все задачи · 4 Привычки · 5 Новая задача`.

### 5.3 `/lite/day?d=tomorrow` и `/lite/week`
- Завтра: встречи (`start_offset=1, from_now=False`) + задачи с дедлайном на
  завтра.
- Неделя: 7 дней вперёд от сегодня, по дням: встречи и задачи с дедлайном на
  этот день (`notion.get_deadline_between`). Пустые дни — одной строкой «—».

### 5.4 `/lite/tasks` — Все задачи
Три секции: Просрочено / Сегодня / Остальные (порядок и сортировка — как в
`/api/tasks`). У задач с дедлайном показывать дату `ДД.ММ`. «Остальные» —
первые 30, дальше ссылка «ещё» (`?all=1`), чтобы уложиться в бюджет страницы.

### 5.5 `/lite/task/{id}` — карточка задачи
Название, зона, приоритет, дедлайн. Действия — отдельные формы-кнопки:
- **Готово** → `notion.close_task`
- **На завтра**, **+1 неделя**, **Без даты** → `notion.reschedule_task`
- **Назад**

Удаление задачи в Lite **не делать** (на кнопочном телефоне слишком легко
нажать случайно; удаление остаётся в основном интерфейсе).

Данные задачи брать из уже загруженных списков по `id`; отдельный запрос
страницы Notion — только если задача в них не найдена. Если не найдена и там —
страница «задача не найдена» со ссылкой назад, не 500.

### 5.6 Замена эмодзи текстом
- Приоритеты: в списках — оформлением карточки (п. 7); в карточке задачи —
  словом без эмодзи («важное», «обычное», «когда-нибудь»).
- Зоны: выводить название без эмодзи (отрезать ведущий эмодзи и пробел).
- Эмодзи календарей (`ev["emoji"]`) не выводить.

В Notion при записи уходят **исходные** значения с эмодзи (см. список в
`README.md`, раздел «Задачи») — соответствие хранить в одном словаре в
`lite.py`.

### 5.7 `/lite/habits?date=YYYY-MM-DD` — Привычки
- Переключатель Сегодня / Вчера / Позавчера — три ссылки. Дату валидировать
  существующим `_clamp_habit_date`.
- Список — та же выборка, что в `/api/habits` (учёт расписания
  `habit_scheduled`, порядок, заголовки групп, серия).
- Тип «Да/Нет»: строка `[x] Название (серия N)` и кнопка «отметить» / «снять».
- Тип «Число»: текущее значение, цель и единица; поле `type="number"`
  (`step="any"`) и кнопка «ок». `done` = значение ≥ цели, если цель задана;
  иначе `done=True` при любом введённом значении — **сверить с тем, как это
  делает `static/app.js`, и повторить точно**.
- «Вода»: ввод в стаканах, в Notion уходит литры (стакан = 0,2 л, константа
  `WATER_GLASS_L` в `static/app.js`). Повторить поведение фронта, константу
  продублировать в `lite.py` с комментарием-ссылкой на `app.js`.
- Запись — через `notion.log_habit`.

### 5.8 `/lite/new` — Новая задача (вторая очередь, см. п. 9)
Поля: название (текст), зона (`<select>`, по умолчанию «Бизнес»), приоритет
(`<select>`, по умолчанию «Обычное»), дедлайн (`<select>`: без даты / сегодня /
завтра / через неделю). Запись — `notion.create_task`. Пустое название —
вернуть форму с сообщением.

## 6. Вход и сессия

Вводить длинный пароль с цифровой клавиатуры неудобно, поэтому:

- Новая необязательная переменная окружения **`LITE_PIN`** (только цифры,
  минимум 6). Если не задана — Lite целиком отключён: все `/lite/*` отдают 404.
- Вход по PIN выдаёт **отдельную** cookie `paola_lite` (подпись тем же
  `SECRET_KEY`, но с другим `salt`, чтобы её нельзя было подставить как
  основную сессию и наоборот). Срок — 90 дней. Флаги: `HttpOnly`, `Secure`,
  `SameSite=Lax`.
- Cookie `paola_lite` даёт доступ **только** к `/lite/*`. К `/api/*` она
  доступа не даёт; существующий `auth_middleware` не ослаблять.
- Защита от перебора: не больше 5 неудачных попыток за 15 минут на весь сервис
  (счётчик в памяти процесса), дальше — 429 с текстом «попробуйте позже».
  Сравнение PIN — `hmac.compare_digest`.
- Неавторизованный запрос к `/lite/*` → редирект 303 на `/lite/login`.
- `/lite/logout` — POST, удаляет cookie.

CSRF: достаточно `SameSite=Lax` + все изменения только через POST. GET-запросы
ничего не меняют.

## 7. Вёрстка

- `<!DOCTYPE html>`, `<meta charset="utf-8">`,
  `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Один встроенный `<style>` (≤ 3 КБ). Запрещено: flex `gap`, grid, CSS-переменные,
  `calc`, веб-шрифты, SVG, картинки, favicon-запросы сверх неизбежного.
- Визуал — в палитре «Небо» основного интерфейса (значения взять из
  `static/style.css`, прописать цвета литералами, без CSS-переменных): фон
  `#E9EDF1`, карточки `#F5F8FB` с рамкой `#DBE4EC` и скруглением 10px, текст
  `#1F2731`, второстепенный `#7C8B9A`, акцент `#3E6187`, просрочка `#C05038`,
  выполнено `#4E9A8E`.
- Шапка страницы — плашка цвета акцента: заголовок системным шрифтом с
  засечками (`Georgia, serif`), под ним дата или подзаголовок.
- Каждая встреча, задача и привычка — отдельная карточка. Время встречи —
  жирным цветом акцента. Важная задача — цветная полоса слева (акцент),
  просроченная — полоса цвета просрочки, «когда-нибудь» — приглушённый текст.
- Кнопка «Готово» — заливка цветом «выполнено», остальные действия — светлые
  кнопки с рамкой. Меню разделов — полоса внизу страницы в потоке документа
  (без `position: fixed`).
- Основной шрифт системный, 18–20px, межстрочный ≥ 1.4. Веб-шрифты основного
  интерфейса (Playfair Display, Golos Text) не подключать.
- Фокус: `a:focus, button:focus, input:focus, select:focus` — заливка цветом
  акцента со светлым текстом. Это главный элемент навигации, он должен быть
  заметнее любого другого выделения на странице.
- Различия нельзя кодировать только цветом: у просроченного есть заголовок
  секции и дата, у выполненной привычки — знак `✓`.
- Порядок элементов в HTML = порядок обхода D-pad. Самое нужное — выше.
- Кнопки и ссылки — блочные, во всю ширину, с отступами: по ним должно быть
  легко попасть и курсором.
- Пункты меню пронумерованы в тексте; дополнительно проставить
  `accesskey="1"`…`"5"` (сработает не во всех браузерах — это бонус, не опора).

## 8. Ошибки

- Сбой Notion/Google → страница Lite с коротким текстом (использовать
  `_notion_hint`) и ссылкой «повторить». Никогда не JSON и не трейсбек.
- Сбой календаря не должен ронять экран с задачами, и наоборот: блоки
  независимы (как сделано в `/api/analytics` через `return_exceptions=True`).

## 9. Очерёдность

1. **Первая очередь:** вход, Сегодня, Завтра, Неделя, Все задачи, карточка
   задачи с действиями, Привычки.
2. **Вторая очередь (после проверки первой на телефоне):** Новая задача.
   Зависит от того, какой ввод текста реально доступен на аппарате.

Не входит в ТЗ: создание и правка событий календаря (сейчас у приложения
доступ к Google Calendar только на чтение — `calendar.readonly`; запись
потребует смены scope и переавторизации — отдельное решение Юлии), аналитика
недели, план следующей недели, консунтиво Generali, уведомления.

## 10. Что не трогать

- Всё вне `paola-app/` (в первую очередь `bot.py`).
- Поведение `/`, `/api/*`, `static/*` — только рефакторинг-вынос общей
  функции из `get_tasks()` без изменения ответа.
- Логику статусов и полей базы «Задачи», базы Generali.

## 11. Приёмка

Исполнитель проверяет сам и показывает результаты:

1. Каждая страница открывается и работает в Chromium **с отключённым
   JavaScript**, все действия выполнимы только клавиатурой (Tab/Enter).
2. Размер HTML каждой страницы на реальных данных ≤ 15 КБ; на страницу —
   ровно один HTTP-запрос (нет внешних ресурсов).
3. Скриншоты всех экранов в окне 360×640.
4. Без cookie: `/lite` → редирект на логин; `/api/tasks` с одной только
   cookie `paola_lite` → 401; 6-я неверная попытка PIN → 429; без `LITE_PIN`
   → 404.
5. Отметка привычки, закрытие и перенос задачи доходят до Notion (проверять
   на тестовой задаче и тестовой отметке, после проверки вернуть как было).
6. Основной интерфейс `/` работает как раньше; ответ `/api/tasks` не изменился.
7. `git diff --stat master -- . ':!paola-app'` пуст.

Финальную проверку на самом 501SH делает Юлия: вход, навигация D-pad,
отметка привычки, закрытие задачи, скорость по мобильной сети.

## 12. Ручные шаги для Юлии

- Railway → сервис Паола App → Variables: добавить `LITE_PIN`.
- Если на шаге 0 выбран обход A — настройка домена в Cloudflare и Railway.
- После деплоя: добавить `https://<домен>/lite` в закладки браузера телефона.
